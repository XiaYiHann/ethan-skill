# 八问输出规范

按原版 DARPA 8 问顺序输出。以下规则定义每一问的合格线与常见失败写法。

- **Q1. 你要做什么？（禁用行话）**
  - 禁的是「没有解释的术语堆砌」，不是名词本身：核心对象必须点名真名（如 KV cache、latent/循环态），名词一出现就紧跟一句高中生能懂的解释（谁随什么增长、谁固定不变）。
  - 指称必须落地：禁止只有性质没有名字的写法——「一种线性增长、一种固定」迫使读者猜指称，猜错全错；正确形态是 named object + plain explanation。
  - 仍需避免：未解释的内部实现类名、缩写连用、公式符号堆砌；机制可用简单算术关系描述（如「可进人数 = 总容量 ÷ 每份占用」）。
- **Q2. 今天是怎么做的？它的局限是什么？（锁定一手痛点）**
  - 阐明现有工业界前沿（SOTA）的通常做法。指出其设计盲区，并具体到代码层或系统机制层的缺陷表现。
- **Q3. 你的方法新在哪里？凭什么相信它会成功？（机理与证据）**
  - 说明新机制或数学模型的本质不同。为什么这个方法在理论上或者小尺度验证上能够成立。
- **Q4. 谁在乎？如果成功了，有什么实质改变？（真实价值与影响面）**
  - 刺破虚假需求。说明哪个具体群体的核心指标（吞吐、延迟、成本、稳定性）会发生实质性的阶跃变化。
- **Q5. 有什么风险？（最致命的 3 个脆弱点）**
  - 列出最可能导致该项目全盘失败或无法成立的技术风险、假设前提或边界条件。
- **Q6. 成本是多少？（核实真实软硬件与试错开销）**
  - 实事求是统计研发、调试、验证过程中的算力资源、耗时、试错成本。
- **Q7. 需要多久？（里程碑划分）**
  - 明确划分“已完成的闭环阶段”与“剩余需要的防御性验证/工程交付阶段”。
- **Q8. 中期考试与期末考试是什么？（带可证伪条件与合格标准）**
  - 明确设立 Mid-term Exam 与 Final Exam。每一个考试必须具备明确的通过线与**一票否决的反证判定标准（Falsification Criteria）**。
